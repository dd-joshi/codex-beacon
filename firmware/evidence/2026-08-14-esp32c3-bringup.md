# ESP32-C3 Super Mini bring-up — 2026-08-14

## Scope

This is the first clean P1 firmware bring-up after removing the superseded
nine-file Arduino attempt. It records only reproducible engineering evidence;
it contains no Wi-Fi credential or device secret.

## Target

- ESP32-C3 Super Mini, ESP32-C3 revision v0.4
- 4 MiB embedded XMC flash
- Native USB Serial/JTAG on COM12
- Frozen prototype wiring: GPIO3 WS2812, GPIO10 active-low button, optional
  GPIO0/ADC1 ambient input, GPIO1 reserved and untouched

## Build and host verification

- PlatformIO Espressif32 platform: `6.13.0`
- ESP-IDF: `5.5.3`
- Application image: 942,058 bytes of a 3 MiB factory partition (29.9%)
- Static RAM: 33,596 bytes of 327,680 bytes (10.3%)
- Native renderer/strict-JSON tests: 7/7 passed
- Desktop protocol/repository tests: 37/38 passed. The remaining check invokes
  `git check-ignore` and cannot run in this exported workspace because `.git`
  metadata is absent; it is not a firmware or protocol failure.

## Flash and recovery evidence

- The original complete 4 MiB flash was captured before programming at
  `firmware/.backups/esp32c3-COM12-before-peri6-20260814-205501.bin`.
- Backup SHA-256:
  `77745ec5cafe436b02eeb52bab207f20239e9cb6c06e73439e0e3392937df234`
- PlatformIO/esptool programmed the bootloader, partition table, and application

## Live firmware evidence

The application emitted consecutive 60-second health reports after flashing:

```text
metrics min_heap=260304 largest_block=122880 max_frame=0 max_body=0 worst_led_us=307
```

The values remained stable at subsequent 120-second and 180-second reports.
With no ignored local configuration present, the expected runtime state is
fail-safe unconfigured: all LEDs off, with Wi-Fi, mDNS, and WebSocket disabled.
